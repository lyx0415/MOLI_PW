项目名称：陪玩店入职管理与展示系统（全栈）

核心目标：基于 Windows 本地开发环境，构建一个包含入职申请、后台审核、入职公示三个模块的陪玩管理网站。

技术栈规范：

前端：Vue 3（组合式 API） + Vite + Element Plus（UI组件库）+ Axios

后端：Node.js + Express 框架

数据库：MySQL 8.0（使用 mysql2 驱动）

联调：后端默认监听 http://localhost:3000，前端默认监听 http://localhost:5173，需配置 CORS 跨域支持

数据库结构（MySQL DDL 要求）：

库名：peiwang_db（字符集 utf8mb4）

表1 applications（申请表）：字段包括 id(自增主键), name, phone, game_type, rank, intro(TEXT), status(TINYINT, 0=待审核, 1=已通过, 2=已拒绝), created_at(DATETIME)。

表2 players（陪玩信息表）：字段包括 id(自增主键), name, game_type, rank, intro(TEXT), hired_at(DATETIME)。（注：审核通过时，需将申请数据同步插入此表）。

后端 RESTful API 接口规范：

POST /api/apply：接收 {name, phone, game_type, rank, intro}，插入 applications 表，状态默认为 0。

GET /api/applications：获取所有申请列表（含状态字段），支持按 status 查询参数筛选。

PUT /api/applications/:id/status：根据 ID 更新状态（接收 {status}），若状态更新为 1（通过），则将该记录同步 INSERT 到 players 表。

GET /api/players：获取所有已入职陪玩列表（仅展示 players 表数据）。

前端页面模块需求：

申请入职页（公开）：包含表单（姓名、联系方式、擅长游戏、段位、自我介绍）及提交按钮；提交后弹窗提示成功，并清空表单。

后台管理页（开发者查看）：以表格展示所有申请记录（含时间、状态）；每条记录带“通过”和“拒绝”按钮；状态变更后表格即时刷新；顶部有筛选下拉框（全部/待审核/已通过/已拒绝）。

已入职陪玩展示页（公开）：以卡片网格（Card Grid）形式展示 players 表中的所有陪玩信息（姓名、游戏、段位、简介）。

部署与环境要求：

使用 npm init -y 初始化后端，依赖安装 express mysql2 cors body-parser nodemon。

使用 npm create vite@latest frontend -- --template vue 初始化前端。

提供 server.js 启动后端，npm run dev 启动前端。

代码需包含连接数据库的详细配置（主机 localhost，端口 3306，用户名 root，密码需预留变量）。
