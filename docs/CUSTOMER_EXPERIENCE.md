# 客户优先的发现与预约体验

2026-10-28。首页以正在选择陪玩、准备下单的客户为主要使用者；陪玩入驻为次级流程，运营管理保持在授权员工工作区。

## 页面与入口

| 页面                            | 用途与入口                                                   |
| ------------------------------- | ------------------------------------------------------------ |
| `/`、`/players`                 | 同一客户发现页，搜索游戏/服务/昵称，比较价格与介绍，选择陪玩 |
| `/players/:id`                  | 核对服务、时长、日期、费用，创建预约；返回保留发现页筛选     |
| `/orders`、`/account`           | 客户订单、资料和收藏；收藏需先登录                           |
| `/experiences/:category?`       | 客户按场景与城市查找服务                                     |
| `/apply`                        | 公开入驻说明，登录客户填写申请；入口位于页脚与次级链接       |
| `/admin`、`/support`、`/studio` | 仅在对应员工账号菜单中提供入口，进入后显示员工导航           |

管理接口和页面继续执行服务器鉴权、角色与归属检查。隐藏入口只改变公共页面的信息层级，不替代访问控制；客户不能通过输入管理地址获得权限。

## 对应后端数据

`GET /api/site` 保留旧字段，新增：

- `gameCatalog[]`：`name`、`providerCount`、`minRateCents`。仅统计活跃账号下已上架且已审核的线上服务，人数按陪玩去重；没有服务时人数为 0、最低价为 `null`。
- `booking`：`enabled`、`timeZone`、`minMinutes`、`maxMinutes`、`stepMinutes`。开放状态来自已配置的支付适配器；时长边界与订单校验共用规则。
- `counts.providers`：只统计至少有一项公开服务的活跃陪玩，与客户实际可发现的范围一致。

`GET /api/providers` 增加 `recommended` 排序和服务说明。关键词同时支持游戏、服务名称、技能及公开昵称/介绍；关键词、类别、城市与预算约束同一服务，卡片最低价及默认进入的服务来自匹配结果。未审核或下架服务不会因关键词匹配而公开。

公开数据不包含账号邮箱、联系方式、支付密钥或管理权限字段。评分与成交继续来自真实已完成订单，不播种虚假历史。

## 本地展示数据

当前本地空库使用 `npm run demo:seed` 建立演示数据：1 位客户、6 位陪玩、管理员和客服各 1 位；6 项线上游戏服务与 5 项线下场景示例。订单和评价初始均为零。

本地账号使用随机临时密码，访问说明仅保存在被 Git 忽略的 `work/CUSTOMER_DEMO.md`；`.env`、数据库和密码不进入代码仓库。首次开发安装可按 README 设置 `DEMO_MODE`、自行设置 `DEMO_PASSWORD` 后播种，禁止把演示数据库用于生产。已有账号和订单不需要清空或重建。

没有商户支付配置时可浏览资料与档期，页面明确显示预约尚未开放。支付与退款流程由隔离测试适配器验收，不进行真实扣款。

## 验证与升级

- SQLite 后端 34 项：包括目录统计、无支付渠道状态、关键词与匹配服务价格、原有鉴权和订单回归。
- Edge 浏览器 16 项：包括客户首页、收藏与取消收藏、公开申请说明、隐藏员工入口、禁止客户调用管理接口、带条件返回和原有完整下单/售后流程。
- 首页、场景页、兼容发现页在 320/390/768/1024/1440px 下无页面横向溢出；桌面和手机截图已检查。
- 生产构建、Prettier 和差异检查通过。GitHub CI 另行运行 MySQL、Chromium 和 npm 生产依赖审计。

本次无数据库结构迁移。升级执行 `npm ci`、`npm run build` 并同步部署前后端、重启服务；保留原有数据库与商户配置。真实商户、SMTP、公网环境和应用 Docker 部署未在本次本地修改中联调。
