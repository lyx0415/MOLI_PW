# 从旧版迁移

1. 在正式切换前备份整个旧 MySQL 库，并保留旧版本的运行包及配置。
2. 在同库或独立新库运行 `npm run db:migrate`。迁移只创建 `moli_*` 表，不覆盖原 `applications` 和 `players`。
3. 创建新管理员并设置新密码；旧源码公开过的管理员与数据库默认密码仍应在原环境更换。仅移除源码默认值不能撤销历史泄露。
4. 旧 `players` 没有可信的登录账号关联，不应自动生成公开默认密码。邀请原陪玩本人注册新账号，重新申请并由运营者核验身份、技能和历史记录，再开放服务和档期。
5. 旧申请联系方式只用于获得授权的审核联系，不直接公开。旧记录继续留在原表作为只读历史，按运营者的数据保留政策处理。
6. 在独立测试环境验收账号、预约、支付、退款、接单和客服后，再将域名流量切换到新服务。不要让两个版本同时接收新订单。
7. 需要回退时先暂停新订单，备份 `moli_*` 新交易记录与支付账目，核对已收款/退款事实。可以切回旧展示站，但不能丢弃新平台已经产生的真实资金记录。

原 `init.sql` 为旧系统脚本，新平台安装以 `backend/migrations/` 为准。应用维护脚本只清理过期会话、验证码和超时未付款订单，不删除历史交易或原表。
