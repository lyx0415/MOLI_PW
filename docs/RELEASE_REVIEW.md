## 发现与处理

| 优先级 | 原问题 | 处理结果 |
| --- | --- | --- |
| 高 | 退款申请释放档期，拒绝退款时可能恢复成重叠订单 | 退款待处理/处理中继续占用档期，确认退款才释放；恢复旧版本订单时再次锁定陪玩并检查冲突 |
| 高 | 登录验证与创建会话之间发生密码重置，旧密码仍可能取得新会话 | 创建会话前锁定并复核最新密码哈希与账号状态；修改密码也检查是否已被其他操作重置 |
| 高 | 缺少独立客服权限，只能共享管理员处理工单 | 增加 `support` 角色、客服工作台和管理员授权/撤权；仅已验证邮箱的正常客户账号可授权，变更终止原会话 |
| 中 | 工单只有一条可覆盖回复，用户无法追问，多人同时处理会丢失结果 | 追加式沟通历史、追问重开、基于更新时间的并发校验；冲突返回 409，页面保留输入并加载新消息 |
| 中 | 所有用户共享 IP 请求额度，同一办公网络中的账号会互相限流 | 已登录 API 按账号计数，匿名 API 仍按 IPv4/IPv6 地址计数；登录/验证码保留单独的 IP 防滥用限制 |
| 中 | 多个管理列表固定截断，旧工单、结算与审计记录无法翻页 | 管理列表及个人工单统一返回 `items/total/page/size`，可分页访问；时间相同时使用 ID 排序 |
| 中 | 小数、非有限数及结构化分页参数生成非法 LIMIT/OFFSET | 统一规范为有界整数；异常参数回退默认值 |
| 中 | 快速切换后台页签，迟到响应覆盖当前表格 | 按请求序号接收最新结果，卸载后不再写入状态 |
| 部署 | 锁文件依赖非官方镜像，受限环境无法安装 | 仅将下载主机调整为 npm 官方源，版本与 integrity 哈希保持不变；Docker 可选挂载代理 CA，TLS 验证保持开启 |

## 客服使用与升级

1. 员工通过正式邮箱验证注册客户账号；管理员在「账号管理」中点击「设为客服」。存在待处理入驻申请的账号需先完成处理；陪玩和管理员账号不可直接转为客服。
2. 员工重新登录后进入「客服工作台」。可查看工单、保留处理历史、回复并标记解决；客户或陪玩补充情况后重新进入处理队列。
3. 客服不能查询任意订单、付款资料、结算、审核或账号管理。关联订单的退款和资金处理由管理员完成，所有授权与工单回复均记录审计。
4. 升级前备份数据库，部署前后端同一版本。启动会应用 `003-support.sql`；不修改已执行的旧迁移。已有 `reply` 字段保留，并迁入历史记录。
5. 自行接入 API 的客户端须同步适配分页对象；员工回复和用户追问须传入消息查询返回的 `ticket.updated_at`，字段名为 `updatedAt`。遇到 409 必须重新读取后再提交。
